### 1.11 全局提示（toast）口径

为避免提示泛滥与口径不一，操作反馈按「是否长周期」区分：

- **长周期操作**（探索、训练等需要等待的操作）在**开始**时弹一条 toast
  （「探索已开始」「开始训练：…」）；**不做完成提醒**，完成态由训练队列、
  星图节点等就地状态呈现，避免为离线完成引入额外通知逻辑。
- **资源消耗操作**（建造升级等）受理成功时给出开始确认 toast
  （「开始建造：…」），与探索/训练口径一致。
- **即时且自明的操作**（装备/卸下遗物、合成、领取挑战等）不弹 toast，
  以数值与卡面状态就地反馈。
- **失败/拒绝**（槽位已满、材料稀有度不一致等）仍用 toast 说明原因，属例外。
- **时长口径**：视图级 Toast 默认 2s 自动消失，一次一条（后到顶替前一条，
  非排队）；成就 Toast 2.5s 排队单条；个别场景可调时长（导出/导入提示 3s/5s）。

落地范围：探索开始（既有）、训练开始与建造开始（v0.77 新增）。

### 1.12 批量购买口径（v0.86，按钮文案口径 v1.00 修订）

等级型购买入口（建筑升级、转生树无限天赋、遗物强化）提供
×1/×10/×100 段位切换，点击按当前段位执行：

- **买满语义**：预算中途耗尽或达等级上限时自然停止（能买几级买几
  级），一级都买不起时按钮禁用；不要求全款买满整个段位。
- **成本预览**：段位 >1 时，建筑升级与无限天赋的成本行展示实际可买
  级数与预计总花费（按当前资源逐级累计，与实扣一致）；段位 ×1 时
  维持单级单价显示。
- **记账粒度与连点一致**：批量内部逐级复用单次原子操作，成就、周
  挑战等逐级计数，与手动连点 N 次完全等价。
- **切换器位置**：建造页在页头（扇区标签上方，全卡共用）；转生树
  在「无限天赋」区标题行内（买断区不显示）；遗物强化在弹窗按钮行。
- **主按钮文案**：段位 >1 时按当前资源实际可完成级数显示
  （「升级 ×3」「购买 ×12」「强化 ×2」，随资源与等级变化）；
  一级都买不起时退回原文案（与禁用态一致），段位 ×1 时保持原
  文案，默认态与既有行为一致。
- **自动化协议不受影响**：自动建造仍为每建筑每 tick 至多 1 级，
  与手动批量是两条独立通道。

## P2-7 状态色语义规范

> **边界声明**：本文档是状态色语义（amber 警告 / alert 不可逆 / locked 锁定）的唯一出处；色彩调色板定义见《氛围视觉规范》，该册不定义语义

### 2.1 设计目标

建立严格的状态色语义体系，解决当前问题：

| 当前问题 | 影响 | 解决方案 |
|---|---|---|
| 锁定态无专用色，借用 `--color-t-tertiary`（灰） | 锁定与 disabled 难以区分 | 新增 `--color-locked`（灰蓝） |
| `--color-alert`（红）被泛用 | 锁定、不可用、危险操作都用红，误导玩家 | alert 仅限不可逆操作 |
| disabled 规范缺失 | 各组件 disabled 表现不一致 | 统一 disabled 规范 |

### 2.2 新增 Token

在 `style.css` `:root` 中新增：

```css
/* —— 状态色（P2-7）—— */
--color-locked: #6387AB;  /* 灰蓝，锁定态专用（v0.83 提亮以满足 WCAG AA ≥4.5:1） */
```

### 2.3 状态色语义体系

#### 完整状态色映射

| 状态 | Token | 色值 | 语义 | 使用场景 | 禁止用于 |
|---|---|---|---|---|---|
| 正常 | `--color-t-primary` | #E8EDF5 | 默认可用 | 正常文本/数值 | — |
| 次要 | `--color-t-secondary` | #8B96A8 | 辅助信息 | 描述、标签 | — |
| 弱化 | `--color-t-tertiary` | #7A8699 | 最弱文本 | 时间戳、占位 | ❌ 锁定态（用 --color-locked） |
| 锁定 | `--color-locked` | #6387AB（v0.83） | 条件未满足 | 未解锁建筑/科技/节点 | ❌ disabled（用 opacity） |
| 警告 | `--color-amber` | #FFB627 | 注意但非危险 | 资源不足提示、稀有物品 | ❌ 不可逆操作 |
| 危险 | `--color-alert` | #F43F5E | 不可逆/破坏性 | 删除、放弃、重置 | ❌ 锁定（用 --color-locked） |
| 禁用 | — | — | 不可交互 | disabled 按钮/卡片 | 通过 opacity + cursor 实现 |

#### 状态色层级（从弱到强）

```
正常 → 次要 → 弱化 → 锁定 → 警告 → 危险
 #E8EDF5  #8B96A8  #7A8699  #6387AB  #FFB627  #F43F5E
 白色     灰       深灰     灰蓝     琥珀     红
```

### 2.4 `--color-locked` 详细规范

#### 色值推导

| 维度 | 说明 |
|---|---|
| 色相 | H=210°（蓝灰色调），与 `--color-core`（H=186°）相邻但在蓝色侧，暗示「与核心相关但未激活」 |
| 饱和度 | S=30%（低饱和），与 `--color-t-tertiary`（S=14%）形成区分，比 tertiary 略饱和以表示「有内容但锁定」 |
| 明度 | L=42%（中暗），在深色背景 `--color-surface`（#0E1424，L=10%）上有足够对比度 |
| WCAG 对比度 | vs `--color-surface` #0E1424：对比度 4.88:1（✅ AA 标准；v0.83 调色：原 #4A6B8A 实测 3.29:1 不达标，提亮为 `#6387AB`，色相 H=210° 与饱和度 S=30% 保持不变） |

#### 使用场景

| 场景 | 当前表现 | 迁移后 | 说明 |
|---|---|---|---|
| MapView 未解锁节点名称 | `--color-t-tertiary` | `--color-locked` | 锁定节点用灰蓝，区别于普通弱化文本 |
| MapView 未解锁节点描述 | `--color-t-tertiary` | `--color-locked` | 同上 |
| BuildView 未解锁建筑名称 | `--color-t-tertiary` | `--color-locked` | — |
| TechView 前置科技未满足 | `--color-t-tertiary` | `--color-locked` | — |
| TechView 未满足要求标签 | `--color-alert`（红） | `--color-locked`（灰蓝） | **关键修正**：前置未满足是「锁定」不是「错误」 |
| ArmyView 未解锁单位 | `--color-t-tertiary` | `--color-locked` | — |
| RelicView 未解锁遗物槽 | `--color-t-tertiary` | `--color-locked` | — |

> **实现注记（v0.88 收口）**：锁定名称迁移已全部落地，提示行与锁定卡名称均迁至 `--color-locked`（MapView `.n-locked` / BuildView `.lock-msg` / TechView `.t-req` / ArmyView `.u-locked` / RelicView `.slot-empty`，及 MapView/BuildView/ArmyView 锁定卡名称，v0.88 收口）。

> **实现注记（v0.86）**：空态口径以代码为准——锁定卡仍展示（不过滤）；BuildView 仅当前扇区全部满级触发空态，TechView 仅当前筛选分支全部完成触发，RelicView 以收藏数 `owned.length===0` 触发（详见《体验增强设计规范》§3.2.2）。

#### 锁定图标颜色

锁定状态通常伴随锁图标（🔒），图标颜色也使用 `--color-locked`：

```css
.locked-icon {
  color: var(--color-locked);
  /* 图标尺寸 var(--icon-sm) = 14px */
}
```

#### 锁定态卡片示例

```css
/* MapView 未解锁节点 */
.stronghold-item.locked {
  opacity: 1;  /* 不降低 opacity，避免与 disabled 混淆 */
}
.stronghold-item.locked .n-name {
  color: var(--color-locked);
}
.stronghold-item.locked .n-desc {
  color: var(--color-locked);
  opacity: 0.7;  /* 描述比标题略弱 */
}
.stronghold-item.locked .n-locked {
  color: var(--color-locked);
}
```

> **关键原则**：锁定态**不降低 opacity**，通过颜色（灰蓝）区分。降低 opacity 是 disabled 的语义。

### 2.5 `--color-alert` 使用规范

#### 仅限不可逆操作

| 场景 | 是否使用 alert | 理由 |
|---|:---:|---|
| 删除存档 | ✅ | 不可逆 |
| 重置游戏 | ✅ | 不可逆 |
| 放弃遗物 | ✅ | 不可逆（稀有物品丧失） |
| 转生重置 | ✅ | 不可逆（进度重置） |
| 资源不足提示 | ❌ 用 `--color-amber` | 可逆（等待资源积累） |
| 前置未满足 | ❌ 用 `--color-locked` | 可逆（满足条件后解锁） |
| 部队数量显示 | ❌ 用 `--color-alert` 仅作为军事色 | 见下方说明 |
| 负产出率 | ❌ → 保持 `--color-alert` | 见下方说明 |

> **实现注记（v0.87.1 已修复）**：CostTag 资源不足已改 `--color-amber`（可逆警告级，非危险红）。
> **实现注记（v0.97）**：资源区（TopBar res-pill）与 CostTag 补 `.sr-only` 资源名称文本，读屏不再只播报裸数字；`.sr-only` 工具类定标于 utilities.css。

#### 例外：`--color-alert` 作为系统主色

以下场景中 `--color-alert`（红）不是「危险」语义，而是「军事/战斗系统」的主色，保持使用：

| 场景 | 当前 | 保持 | 说明 |
|---|---|---|---|
| 部队数值颜色 | `--color-alert` | ✅ | 军事系统主色（P1-6 定义） |
| 战斗按钮 | `--color-alert` | ✅ | 战斗系统主色（P1-5 btn-accent） |
| 负产出率 | `--color-alert` | ✅ | 能量流失警示 |
| 训练中行动项 | `--color-alert` | ✅ | 军事系统主色（P1-2） |

> **区分原则**：当 `--color-alert` 用于「数值/标签着色」时是系统主色；用于「按钮/操作」时需判断是否不可逆。

### 2.6 disabled 规范

#### 统一 disabled 样式

disabled 状态通过 **opacity + cursor** 实现，不改变颜色：

```css
/* 全局 disabled 基础规则 */
[disabled],
.disabled,
button:disabled,
.btn-primary:disabled,
.btn-secondary:disabled,
.btn-accent:disabled,
.btn-ghost:disabled {
  opacity: 0.4;
  cursor: not-allowed;
  pointer-events: none;  /* 禁止 hover/active 反馈 */
}
```

#### 按钮各自 disabled 微调

P1-5 已定义各按钮 disabled，本规范统一 opacity：

| 按钮类型 | P1-5 disabled opacity | P2-7 统一 opacity | 变化 |
|---|:---:|:---:|---|
| `.btn-primary` | 0.6 | **0.4** | 降低，更明确「不可用」 |
| `.btn-secondary` | 0.5 | **0.4** | 降低 |
| `.btn-accent` | 0.6 | **0.4** | 降低 |
| `.btn-ghost` | 0.4 | **0.4** | 保持 |

```css
/* 统一 disabled */
.btn-primary:disabled,
.btn-secondary:disabled,
.btn-accent:disabled,
.btn-ghost:disabled {
  opacity: 0.4;
  cursor: not-allowed;
  pointer-events: none;
  /* 保留各自的颜色变化（primary/accent 变灰，secondary/ghost 变透明） */
}

.btn-primary:disabled,
.btn-accent:disabled {
  background: var(--color-elevated);
  color: var(--color-t-tertiary);
  box-shadow: none;  /* 去除 hover 发光 */
}

.btn-secondary:disabled,
.btn-ghost:disabled {
  /* 仅 opacity 降低，保持原有背景透明/深色 */
}
```

#### disabled vs locked 关键区别

| 维度 | disabled | locked |
|---|---|---|
| 语义 | 「不可交互」（按钮置灰） | 「条件未满足」（内容锁定） |
| opacity | **0.4**（明显降低） | **1.0**（不降低） |
| 颜色 | 保持原色 + opacity | `--color-locked`（灰蓝） |
| cursor | `not-allowed` | `pointer`（可查看详情） |
| pointer-events | `none`（禁止交互） | `auto`（可 hover 查看锁定原因） |
| 典型场景 | 资源不足时的升级按钮 | 未解锁的建筑/科技/节点 |

> **核心区分**：disabled 降低 opacity（看起来「变暗不可用」），locked 保持 opacity 但变灰蓝色（看起来「存在但锁定」）。玩家看到 locked 知道「将来可以用」，看到 disabled 知道「当前不能点」。

### 2.7 状态色组合场景

#### 场景一：科技树前置未满足

```
┌──────────────────────────────────┐
│ 🔒 量子计算         ← 名称: --color-locked
│    需要先研究「核聚变」  ← 描述: --color-locked (opacity 0.7)
│                    [研究] ← 按钮: disabled (opacity 0.4)
└──────────────────────────────────┘
```

#### 场景二：资源不足升级

```
┌──────────────────────────────────┐
│ ⚡ 聚变反应堆  Lv.3     ← 名称: --color-t-primary (正常)
│    需要: 1,200 能量     ← 成本: --color-amber (警告，资源不足)
│              [升级]     ← 按钮: disabled (opacity 0.4)
└──────────────────────────────────┘
```

#### 场景三：正常可升级

```
┌──────────────────────────────────┐
│ ⚡ 聚变反应堆  Lv.3     ← 名称: --color-t-primary (正常)
│    产出: +15/s          ← 产出: --color-core (正常青)
│              [升级]     ← 按钮: .btn-primary (正常可点)
└──────────────────────────────────┘
```

#### 场景四：危险操作确认

```
┌──────────────────────────────────┐
│ ⚠️ 确认放弃遗物         ← 标题: --color-alert (危险)
│    此操作不可撤销       ← 描述: --color-t-secondary
│    [取消]    [确认放弃]  ← 取消: btn-secondary / 确认: btn-accent --color-alert
└──────────────────────────────────┘
```

### 2.8 状态色使用决策流程

```
元素是否可交互？
├─ 否 → 纯展示元素
│   ├─ 条件未满足？ → --color-locked
│   ├─ 需要注意？ → --color-amber
│   ├─ 不可逆操作提示？ → --color-alert
│   └─ 正常 → --color-t-primary/secondary/tertiary
│
└─ 是 → 可交互元素
    ├─ 条件未满足？ → disabled (opacity 0.4) + 锁定图标 --color-locked
    ├─ 资源不足？ → disabled (opacity 0.4) + 成本 --color-amber
    ├─ 不可逆操作？ → .btn-accent --color-alert
    └─ 正常 → 正常按钮样式
```

## P2-8 可访问性底线规范

> **定位**：本章是全项目可访问性（a11y）底线的唯一出处。动效降级维度见
> 《动效规范》第六章；弹窗焦点陷阱的组件结构见第 11 册《弹窗与确认流规范》（待建）。

### 8.1 对比度底线

玩家需要读到的文本（成本/倒计时/数值/按钮文字/状态提示），对底色
`--color-void` #05070D 或 `--color-surface` #0E1424，对比度 ≥ 4.5:1（WCAG AA）。

| 文本色 | 色值 | 对比度（vs 暗底） | 定标 |
|---|---|:---:|---|
| `--color-t-primary` | #E8EDF5 | 约 15:1 | ✅ 关键文本任意字号 |
| `--color-t-secondary` | #8B96A8 | 约 5.9:1 | ✅ 辅助文本任意字号 |
| `--color-core` | #00E5FF | 约 9.5:1 | ✅ 强调文本 |
| `--color-locked` | #6387AB | 4.88:1（v0.83 提亮后实测） | ✅ 锁定态 |
| `--color-amber` | #FFB627 | 约 8.6:1 | ✅ 警告文本 |
| `--color-alert` | #F43F5E | 约 5.2:1 | ✅ 危险文本 |
| `--color-t-tertiary` | #7A8699 | 5.46:1 | ✅ 任意文本（v0.88.1 提亮达标） |

> 发光/阴影类视觉（text-shadow、box-shadow 光晕）不计入对比度计算；
> 图标按图形对比度 3:1 口径执行。

### 8.2 `--color-t-tertiary` 处置（已提值达标，v0.88.1）

`--color-t-tertiary` 原值 #6B7589 实测 4.35:1 不达 AA，已于 v0.88.1 提值为
**#7A8699**（程序实算三底色）：

| 底色 | 原 #6B7589 | 现 #7A8699 |
|---|---|:---:|
| `--color-void` #05070D | 4.35:1 | **5.46:1** ✅ |
| `--color-surface` #0E1424 | 3.96:1 | **4.98:1** ✅ |
| `--color-elevated` #182238 | 3.42:1 | 4.30:1（显著提升） |

处置定标：

1. tertiary 恢复为**任意文本可用**的弱化色（不再限用场景），锁定态
   仍用 `--color-locked`（语义不同）。
2. 玩法关键信息的既有约定不变：能用 secondary 就不用 tertiary，
   保持视觉层级习惯。
3. 后续再调 token 色值时按本节三底色口径实算登记。

### 8.3 焦点策略

```css
/* src/styles/base.css 全局规则 */
:focus-visible {
  outline: 2px solid var(--color-core);
  outline-offset: 2px;
}
```

| 项 | 定标 |
|---|---|
| 焦点环 | 2px `--color-core` 描边 + offset 2px，仅 `:focus-visible` 显示（鼠标点击不打扰） |
| 弹窗焦点 | ModalOverlay 挂 useFocusTrap：打开即陷阱内聚焦、Tab 循环、Escape 关弹窗（v0.77） |
| 键盘可达目标 | 可点击容器 role=button + tabindex=0 + Enter/空格（v0.77 装备槽、v0.84 核心）；卡片主操作平铺为原生按钮（v0.96 图鉴卡装备/选材、编队卡行内按钮） |

### 8.4 aria 命名模式

| 模式 | 使用场景 | 实例 |
|---|---|---|
| `role="dialog"` + `aria-modal="true"` | 模态弹窗、引导气泡 | ModalOverlay、OnboardingBubble |
| `role="status"` + `aria-live="polite"` | 瞬时提示不抢焦点 | Toast（v0.84）、OnboardingBubble、AchievementToast、满槽训练倒计时（v0.87） |
| `aria-expanded` | 可展开面板 | UpgradeCountdown 明细面板、BottomNav「更多」面板（v0.95） |
| `aria-controls` | 展开控件与被展开容器关联 | BottomNav「更多」按钮 → 面板（v0.95） |
| `aria-label` | 无文本图标按钮/区域 | 侧栏折叠、侧栏折叠态导航项（v0.95）、存档管理区按钮、段位切换组、装备槽、导出存档码文本域、批量切换组（建造/训练/强化） |
| `aria-current` | 当前导航项 | SideNav/BottomNav 当前路由（非导航路由如战斗页不高亮，v0.95） |
| `role="radiogroup"` + `role="radio"` | 单选列表组 | 设置页语言列表（v1.13） |
| `aria-hidden="true"` | 纯装饰 | 图标、粒子、星点、跃迁 overlay |
| `data-testid` | 回归断言锚点（非 a11y，同登记） | endless-section、cd-time 等 |

### 8.5 aria-live 场景

已落地：
- Toast：`role="status"` + `aria-live="polite"`，操作反馈即时播报
- OnboardingBubble：`aria-live="polite"`，引导内容播报
- 成就解锁提示：排队单条 2.5s，AchievementToast 自带 `role="status"` +
  `aria-live="polite"` 播报（不经 Toast 通道）
- 满槽训练倒计时：disabled 按钮载实时剩余「训练中…剩 Xs」，按钮内
  `aria-live="polite"` 区域播报（v0.87 落地）
- 导出存档码：常显只读文本域带 `aria-label="导出存档码"`（v0.87 落地）

### 8.6 键盘交互底线

- Escape 关弹窗 = 点击遮罩同语义（ModalOverlay/OfflineReport 已接）
- 底部导航「更多」面板：Escape 收起并把焦点还给触发按钮（v0.95）
- 弹窗内 Tab 不逃逸（focus trap）
- 卡片 Enter/空格触发 = 点击同语义
- 禁用按钮 hover 不得变色发光（P2-7，v0.87.1 已落地：hover 限定 `:hover:not(:disabled)`，disabled 无 hover 反馈）

### 8.7 加载/常驻态（暂未落地）

busy/loading 态在文档与代码中均不存在（当前仅禁用态）。**登记为暂未落地**，
设计预留方向：

- 按钮 busy 态 = disabled + 内联 spinner 或文字变更（「训练中…剩 Xs」的
  disabled 载信息已是事实先例）
- 自动化建造等长操作不加进行中态（每 tick 1 级即完成，无中间态）
- 未来新增 busy 态时：禁用期间防连点（pointer-events:none 已有）+
  `aria-busy="true"` + 视觉与 disabled 可区分（spinner 或文案）

### 8.8 验收清单

| 验收项 | 标准 |
|--------|------|
| 关键文本对比度 | ≥ 4.5:1（tertiary 限用规则遵守 §8.2） |
| 焦点环 | :focus-visible 2px core + offset 2（鼠标点击不出现） |
| 弹窗焦点 | 打开聚焦陷阱内、Tab 循环、Escape 关闭 |
| 提示播报 | Toast/气泡/成就/满槽倒计时 aria-live=polite（全部已落地） |
| 装饰元素 | 图标/粒子/动效 overlay 全部 aria-hidden |
| 键盘可达 | 可点卡片 Enter/空格；禁用按钮无 hover 反馈 |
