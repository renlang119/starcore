## 一、交互反馈微交互

### 1.1 设计目标与原则

将所有可交互元素的反馈从「功能可用」升级为「操作愉悦」，建立统一的反馈节奏：

| 反馈类型 | 触发场景 | 视觉表现 | 时长 |
|---|---|---|---|
| 卡片悬浮 | 卡片 hover | translateY(-2px) + 发光 | 0.2s |
| 按钮点击 | 按钮 active | scale(0.95) + 回弹 | 0.15s |
| 升级成功 | 升级/研究完成 | flash 闪光 | 0.4s |
| 核心脉动 | 核心被 click | 额外脉动一次 | 0.6s |

四条铁律：

1. **遵循 `prefers-reduced-motion`**：所有反馈在玩家开启「减弱动画」时降级（策略见第六章）
2. **反馈时长 ≤ 0.3s**：hover/active 反馈不超过 0.3s，避免拖沓感（flash 和核心脉动例外，分别为 0.4s/0.6s，属于「事件反馈」而非「交互反馈」）
3. **每个反馈只用于一个场景**：不滥用 translateY、不滥用 flash，每种反馈有明确的触发语义（唯一性约束见 §1.7）
4. **回弹统一使用 `--ease-out`**：`cubic-bezier(.16,1,.3,1)`（已有 Token）

### 1.2 卡片悬浮（hover / active）

#### 适用场景

| 组件 | 场景 | 说明 |
|---|---|---|
| `.action-item.actionable` | 行动队列可执行项 hover | 已落地 |
| `.ov-item` | 文明概况指标 hover | 已落地 |
| `.card`（全局） | 通用卡片 hover | 现行代码无全局 `.card` 类，卡片交互各自挂 `.build-card`/`.tech-card`/`.relic-card` 等视图私有类，本行按「通用类存在时适用」理解 |

> **注意**：`.action-item.in-progress` 不加 hover 上浮（进行中状态不应暗示「可点击操作」，已有脉冲暗示「正在发生」）。

#### 参数规范

```css
/* 卡片 hover 反馈 */
.action-item.actionable:hover,
.ov-item:hover,
.card.interactive:hover {
  transform: translateY(-2px);
  background: var(--color-hover);
  border-color: var(--color-border-glow);
  box-shadow: var(--elevation-2);
  transition: transform 0.2s var(--ease-out),
              background 0.2s var(--ease-out),
              border-color 0.2s var(--ease-out),
              box-shadow 0.2s var(--ease-out);
}

/* active 回弹（按下时取消上浮，改为缩放） */
.action-item.actionable:active,
.ov-item:active,
.card.interactive:active {
  transform: translateY(0) scale(0.98);
  transition: transform 0.1s var(--ease-out);
}
```

#### 参数明细

| 参数 | hover 值 | active 值 | 说明 |
|---|---|---|---|
| `transform` | `translateY(-2px)` | `translateY(0) scale(0.98)` | hover 上浮 2px，active 回落并微缩 |
| `background` | `var(--color-hover)` | 保持 hover 色 | hover 变深 |
| `border-color` | `var(--color-border-glow)` | 保持 glow 色 | 边框变亮 |
| `box-shadow` | `var(--elevation-2)` | 保持 | 升至悬浮阴影 |
| `transition` (hover) | `0.2s var(--ease-out)` | — | 0.2s 进入 |
| `transition` (active) | — | `0.1s var(--ease-out)` | 0.1s 更快回弹 |

#### 主题色发光叠加（仅 actionable 卡片）

`.action-item.actionable` 的 hover 在 Elevation 基础上叠加主题色发光：

```css
.action-item.actionable:hover {
  transform: translateY(-2px);
  background: var(--color-hover);
  border-color: var(--color-border-glow);
  box-shadow: var(--elevation-2),
              0 0 0 1px color-mix(in srgb, var(--c) 20%, transparent);
}
```

> `.ov-item` 不叠加发光（文明概况不需要主题色强调 hover，仅上浮+变色即可）。

### 1.3 按钮点击（active）

#### 适用场景

所有 `.btn-primary`、`.btn-secondary`、`.btn-accent`、`.btn-ghost` 按钮的 active 态。

#### 参数规范

```css
/* 按钮统一 active 反馈 */
.btn-primary:active,
.btn-secondary:active,
.btn-accent:active,
.btn-ghost:active {
  transform: scale(0.95);
  transition: transform 0.1s var(--ease-out);
}

/* 释放后回弹 */
.btn-primary,
.btn-secondary,
.btn-accent,
.btn-ghost {
  transition: transform 0.15s var(--ease-out),
              background 0.15s var(--ease-out),
              box-shadow 0.15s var(--ease-out);
}
```

#### 参数明细

| 参数 | active 值 | 释放后 | 说明 |
|---|---|---|---|
| `transform` | `scale(0.95)` | 回弹至 `scale(1)` | 缩小 5% |
| active `transition` | `0.1s var(--ease-out)` | — | 快速按下 |
| 释放 `transition` | — | `0.15s var(--ease-out)` | 0.15s 回弹 |

> **注意**：规范值为 `scale(0.95)`（缩放幅度 5%，明确可感）。
>
> **豁免注记（v0.83）**：PrestigeView 的 `.btn-transcend`（奇点重启主按钮）保留 active `scale(0.97)` 与 disabled `opacity: 0.5`，为全局统一值（0.95 / 0.4）的刻意豁免——不可逆重操作按压感更轻、禁用态更醒目，作为既有实现认可保留，新按钮不参照此值。

#### 按钮各自 hover 效果保持不变

按钮的 hover 效果（发光、变色）在《组件与按钮设计规范》P1-5 定义，本规范不修改 hover，仅统一 active：

| 按钮类型 | hover 效果（保持） | active 效果（统一） |
|---|---|---|
| `.btn-primary` | bg → core-dim + 发光 0 0 16px | `scale(0.95)` |
| `.btn-secondary` | bg → hover + border glow | `scale(0.95)` |
| `.btn-accent` | brightness(1.1) + 发光 | `scale(0.95)` |
| `.btn-ghost` | bg → hover + color → primary | `scale(0.95)` |

### 1.4 升级成功 flash（设计预留，未落地）

> **未落地核对**：`flashSuccess` / `flashSuccessPlasma` / `.flash-success` / `--flash-color` 在代码中零实现。当前「成功完成」的实际反馈为 TopBar 资源数值的 `resFlash` 闪动（§1.6）+ 成就解锁 Toast；升级/研究/训练成功无专属闪光动效。以下为设计预留。

#### 适用场景

| 触发事件 | 场景 | 说明 |
|---|---|---|
| 建筑升级成功 | BuildView 升级按钮点击后 | 资源扣除、等级+1 |
| 科技研究完成 | TechView 研究完成 | 科技解锁 |
| 部队训练完成 | ArmyView 训练完成 | 部队入列 |

> **注意**：flash 仅用于「成功完成」的正向事件，不用于错误/失败。错误反馈使用 `--color-alert` 抖动（见 §1.8）。

#### 视觉表现

目标卡片（或按钮）短暂闪白光，0.4s 内从亮到消散：

```css
@keyframes flashSuccess {
  0% {
    box-shadow: var(--elevation-1);
  }
  15% {
    box-shadow: var(--elevation-1),
                0 0 0 2px rgba(0, 229, 255, 0.6),
                0 0 24px rgba(0, 229, 255, 0.4);
  }
  100% {
    box-shadow: var(--elevation-1);
  }
}

.flash-success {
  animation: flashSuccess 0.4s var(--ease-out);
}
```

#### 参数明细

| 时间点 | box-shadow | 说明 |
|---|---|---|
| 0% | `var(--elevation-1)` | 起始：正常阴影 |
| 15%（0.06s） | `--elevation-1` + `0 0 0 2px rgba(0,229,255,0.6)` + `0 0 24px rgba(0,229,255,0.4)` | 峰值：青色描边 + 外发光 |
| 100%（0.4s） | `var(--elevation-1)` | 结束：恢复正常 |

| 参数 | 值 | 说明 |
|---|---|---|
| 动画名称 | `flashSuccess` | — |
| 时长 | `0.4s` | 从闪光到消散 |
| 缓动 | `var(--ease-out)` | 快速到达峰值后缓慢消散 |
| 描边色 | `rgba(0, 229, 255, 0.6)` | `--color-core` 60% 不透明度 |
| 发光色 | `rgba(0, 229, 255, 0.4)` | `--color-core` 40% 不透明度 |
| 描边宽度 | `2px` | 明显但不夸张 |
| 发光范围 | `24px` | 超过卡片边界，视觉冲击 |

#### 主题色适配

flash 的颜色可根据事件类型调整：

| 事件类型 | flash 颜色 | rgba | 说明 |
|---|---|---|---|
| 建筑升级 | `--color-core`（青） | `rgba(0, 229, 255, …)` | 建造系统主色 |
| 科技研究 | `--color-plasma`（紫） | `rgba(167, 139, 250, …)` | 科技系统主色 |
| 探索完成 | `--color-quantum`（绿） | `rgba(46, 230, 160, …)` | 探索系统主色 |
| 部队训练 | `--color-alert`（红） | `rgba(244, 63, 94, …)` | 军事系统主色 |

```css
/* 主题色 flash 变体（示例：科技等离子紫） */
.flash-success.plasma {
  animation-name: flashSuccessPlasma;
}
@keyframes flashSuccessPlasma {
  0% { box-shadow: var(--elevation-1); }
  15% {
    box-shadow: var(--elevation-1),
                0 0 0 2px rgba(167, 139, 250, 0.6),
                0 0 24px rgba(167, 139, 250, 0.4);
  }
  100% { box-shadow: var(--elevation-1); }
}
```

> **实现建议**：前端可通过 CSS 变量 `--flash-color` 注入主题色，避免定义多个 keyframes：
> ```css
> @keyframes flashSuccess {
>   0% { box-shadow: var(--elevation-1); }
>   15% {
>     box-shadow: var(--elevation-1),
>                 0 0 0 2px color-mix(in srgb, var(--flash-color, var(--color-core)) 60%, transparent),
>                 0 0 24px color-mix(in srgb, var(--flash-color, var(--color-core)) 40%, transparent);
>   }
>   100% { box-shadow: var(--elevation-1); }
> }
> .flash-success { animation: flashSuccess 0.4s var(--ease-out); }
> ```
> 使用：`<div class="flash-success" style="--flash-color: var(--color-plasma)">`

### 1.5 核心 click 脉动

#### 适用场景

玩家点击 Hero 区的 `.core-visual`（核心能量体）时，核心额外脉动一次，提供「触摸反馈」。

> **注意**：核心已有持续的 `corePulse` 3s 循环动画（见 §4.1），click 脉动是在循环之上叠加的一次性强化脉冲，让玩家感知「我点到了」。

#### 视觉表现（以代码为准）

```css
@keyframes coreClickPulse {
  0% {
    transform: scale(1);
  }
  20% {
    transform: scale(1.12);
  }
  60% {
    transform: scale(0.97);
  }
  100% {
    transform: scale(1);
  }
}

.core-visual.core-clicked {
  animation: coreClickPulse 0.6s var(--ease-out);
}
```

#### 参数明细

| 时间点 | transform | 说明 |
|---|---|---|
| 0%（0s） | `scale(1)` | 起始 |
| 20%（0.12s） | `scale(1.12)` | 峰值：放大 12% |
| 60%（0.36s） | `scale(0.97)` | 回弹：微缩 3% |
| 100%（0.6s） | `scale(1)` | 恢复 |

| 参数 | 值 | 说明 |
|---|---|---|
| 动画名称 | `coreClickPulse` | — |
| 时长 | `0.6s` | 比标准反馈长，属于「事件反馈」 |
| 缓动 | `var(--ease-out)` | — |
| 放大幅度 | 12%（`scale(1.12)`） | 比 hover 的 2% 更大，属于「触摸确认」 |

> **落地注记**：现行实现仅 transform 关键帧，无 filter 亮度变化（早期设计稿含 brightness 关键帧，未落地不回改）。

#### 与 corePulse 循环的叠加

```css
/* 现有：corePulse 循环在 .core-visual::after 和 .core-glow 上 */
.core-visual::after { animation: corePulse 3s ease-in-out infinite; }
.core-glow { animation: corePulse 3s ease-in-out infinite; }

/* click 脉动在 .core-visual 本身上 */
.core-visual { animation: none; }  /* 默认无动画 */
.core-visual.core-clicked { animation: coreClickPulse 0.6s var(--ease-out); }
```

> 两者作用在不同元素上（循环在 `::after` 和 `.core-glow`，click 在 `.core-visual` 本身），不会冲突。

#### 前端实现参考

```vue
<script setup>
const clicked = ref(false)
const onCoreClick = () => {
  clicked.value = true
  setTimeout(() => { clicked.value = false }, 600)  // 动画结束后移除 class
  router.push('/build')
}
</script>

<template>
  <div
    class="core-visual"
    :class="{ 'core-clicked': clicked }"
    @click="onCoreClick"
  >
    <!-- ... -->
  </div>
</template>
```

### 1.6 资源数值变化闪动（已落地）

TopBar 资源 pill 的数值在资源变动（fmt 后字符串不同）时短暂变绿发光，0.3s 一次性：

```css
/* src/components/layout/TopBar.vue */
.res-pill.flash .r-amount {
  animation: resFlash 0.3s var(--ease-out);
}
@keyframes resFlash {
  0% {
    color: var(--color-quantum);
    text-shadow: 0 0 6px rgba(46, 230, 160, 0.6);
  }
  100% {
    color: var(--color-t-primary);
    text-shadow: none;
  }
}
```

| 参数 | 值 | 说明 |
|---|---|---|
| 时长 | `0.3s` | 符合交互反馈 ≤ 0.3s 约束 |
| 峰值色 | `var(--color-quantum)` | 正向增长语义（绿色） |
| 发光 | `text-shadow 0 0 6px rgba(46,230,160,0.6)` | 与峰值色同色系 |

> 与粒子的关系见 §3.6：flash 是「数值变化时的瞬时高亮」，粒子是「持续产出时的动态氛围」，两者互补可同时存在。

### 1.7 反馈唯一性约束

确保每种反馈只用于其语义场景，避免泛滥：

| 反馈 | 唯一语义 | 禁止用于 |
|---|---|---|
| `translateY(-2px)` hover | 「可点击操作」的卡片 | 按钮（按钮用 scale）、进行中卡片（用脉冲） |
| `scale(0.95)` active | 按钮按下确认 | 卡片（卡片用 scale(0.98) 回弹） |
| `flashSuccess` 0.4s | 升级/研究/训练成功 | 错误提示、普通点击、hover |
| `coreClickPulse` 0.6s | 核心被点击 | 其他卡片/按钮 |
| `shakeError` 0.3s | 操作失败/资源不足 | 成功反馈、普通点击 |
| `resFlash` 0.3s | 资源数值增长 | 减少/消耗场景（负值走红色文字静态警示） |

### 1.8 错误抖动（设计预留，未落地）

> **未落地核对**：`shakeError` / `.shake-error` 在代码中零实现。当前操作失败的实际反馈为成本标签 `CostTag` 的 `not-enough` 红色静态着色，无抖动动画。以下为设计预留。

```css
  40% { transform: translateX(4px); }
  60% { transform: translateX(-3px); }
  80% { transform: translateX(3px); }
}

.shake-error {
  animation: shakeError 0.3s var(--ease-out);
}
```

| 参数 | 值 | 说明 |
|---|---|---|
| 动画名称 | `shakeError` | — |
| 时长 | `0.3s` | 符合 ≤ 0.3s 约束 |
| 抖动幅度 | ±4px → ±3px | 递减抖动 |
| 颜色 | 无（不改变元素颜色） | 可选：叠加 `box-shadow: 0 0 0 1px var(--color-alert)` |

> **使用场景**：资源不足时点击升级按钮、未满足前置条件时点击研究等。与 flash-success 形成正负反馈对比。

## 二、路由转场「空间跃迁」

### 2.1 设计目标

将路由切换的简单 opacity fade 替换为「空间跃迁」光效——模拟星际跃迁时的白光闪过 + 微缩放过渡，增强页面切换的沉浸感和科技氛围。

**现状**：`<transition name="warp" mode="out-in">`（AppShell.vue），opacity + scale + 白光 overlay 三重过渡。

### 2.2 动画时序

```
时间轴（out-in 模式，总时长约 0.5s）：

  0ms        200ms       350ms       500ms
  │          │           │           │
  ├──────────┤           │           │
  │  旧页离场  │           │           │
  │ warpOut   │           │           │
  │ scale(1→0.96)        │           │
  │ opacity(1→0)         │           │
  │          ├───────────┤           │
  │          │  光效闪过   │           │
  │          │  overlay   │           │
  │          │  warpFlash │           │
  │          │  峰值 0.7   │           │
  │          │           ├───────────┤
  │          │           │  新页入场  │
  │          │           │  warpIn   │
  │          │           │  scale(1.04→1) │
  │          │           │  opacity(0→1)   │
```

### 2.3 旧页离场（warpOut）

```css
.warp-leave-active {
  animation: warpOut 0.2s var(--ease-out);
}
```

| 参数 | 值 | 说明 |
|---|---|---|
| 时长 | 0.2s | 快速离场 |
| opacity | 1 → 0 | 渐隐 |
| transform | scale(1) → scale(0.96) | 微缩 4% |
| 缓动 | `var(--ease-out)` | 快速开始、缓慢结束 |

### 2.4 新页入场（warpIn）

```css
.warp-enter-active {
  animation: warpIn 0.3s var(--ease-out);
}
```

| 参数 | 值 | 说明 |
|---|---|---|
| 时长 | 0.3s | 略慢于离场，有「展开」感 |
| opacity | 0 → 1 | 渐显 |
| transform | scale(1.04) → scale(1) | 从放大 4% 回落 |
| 缓动 | `var(--ease-out)` | — |

### 2.5 白光 overlay（warpFlash）

AppShell 中渲染全屏 overlay div，路由切换时白光闪过：

```css
.warp-overlay {
  position: fixed;
  inset: 0;
  z-index: 300;
  pointer-events: none;
  background: radial-gradient(
    ellipse at center,
    rgba(255, 255, 255, 0.25) 0%,
    rgba(0, 229, 255, 0.1) 30%,
    transparent 70%
  );
  opacity: 0;
}

/* 触发时 v-if 挂载（AppShell warpFlash ref），直挂动画 */
.warp-overlay {
  animation: warpFlash 0.35s var(--ease-out);
}

@keyframes warpFlash {
  0% { opacity: 0; }
  30% { opacity: 0.7; }
  100% { opacity: 0; }
}
```

| 参数 | 值 | 说明 |
|---|---|---|
| overlay 位置 | fixed inset 0 | 全屏覆盖 |
| z-index | 300 | 高于模态（200），`pointer-events: none` 不挡交互 |
| 背景渐变 | 椭圆中心白光 25% → 青 10% → 透明 70% | 模拟跃迁光波 |
| 峰值 opacity | 0.7 | 不完全遮挡，透出底层 |
| 闪过时长 | 0.35s | 与离场 0.2s + 入场 0.3s 交叠，在中间触发 |
| 缓动 | `var(--ease-out)` | — |

### 2.6 触发机制（以代码为准）

实现采用 `watch(route.path)` + 防抖定时器 + `v-if`，而非 transition 生命周期钩子：

```ts
// AppShell.vue
const warpFlash = ref(false)
let warpTimer: ReturnType<typeof setTimeout> | null = null
watch(
  () => route.path,
  () => {
    // 防抖：新触发先清旧 timer，避免上一次的熄灭回调提前中断本次白光
    if (warpTimer) clearTimeout(warpTimer)
    warpFlash.value = true
    warpTimer = setTimeout(() => {
      warpFlash.value = false
      warpTimer = null
    }, 350)
  }
)
```

| 机制 | 实现 | 说明 |
|---|---|---|
| 触发点 | `watch(() => route.path)` | 每次路由变化触发 |
| overlay 显隐 | `v-if="warpFlash"` + 直挂 `warpFlash 0.35s` 动画 | 挂载即播放，350ms 后卸载 |
| 防抖 | `clearTimeout` 先清旧 timer | 快速连续切换时白光不中断 |
| 离场/入场 | `<transition name="warp" mode="out-in">` | 类名仅承载 keyframes 绑定（animations.css `.warp-enter-active`/`.warp-leave-active`） |

### 2.7 性能考量

| 考量 | 措施 |
|---|---|
| transform/opacity 均为 GPU 加速属性 | 不触发 layout/paint，仅 composite |
| overlay 使用 radial-gradient | 静态背景，不每帧重绘 |
| overlay pointer-events: none | 不拦截交互 |
| 动画时长总计约 0.5s | 不拖沓，玩家可接受 |
| `out-in` 模式 | 旧页完全离开后新页才入场，无重叠渲染负担 |

## 三、资源产出粒子

### 3.1 设计目标与约束

当 TopBar 资源 pill 的产出率 `rate > 0` 时，在 pill 旁显示向上流动的光点粒子，直观传达「资源正在增长」的动态感。

设计约束：
- 性能优先：5 种资源 × 粒子数量需严格控制，避免每秒大量 DOM 操作
- 视觉克制：粒子是「锦上添花」，不喧宾夺主
- 遵循 `prefers-reduced-motion`（见 §3.7 与第六章）

### 3.2 单粒子样式与关键帧（以代码为准）

```css
/* TopBar.vue scoped */
.res-particle {
  position: absolute;
  top: 50%;
  right: 4px;
  width: 2px;
  height: 2px;
  border-radius: 50%;
  background: var(--c, var(--color-core));
  box-shadow: 0 0 4px var(--c, var(--color-core));
  pointer-events: none;
  z-index: 1;
  animation: particleRise var(--duration, 1s) var(--ease-out) forwards;
}

/* animations.css */
@keyframes particleRise {
  0% {
    opacity: 0;
    transform: translateY(0) scale(0.5);
  }
  20% {
    opacity: 1;
    transform: translateY(-6px) scale(1);
  }
  100% {
    opacity: 0;
    transform: translateY(-28px) scale(0.8);
  }
}
```

#### 参数明细

| 参数 | 值 | 说明 |
|---|---|---|
| 粒子尺寸 | 2px × 2px | 极小光点 |
| 形状 | border-radius: 50%（圆形） | — |
| 颜色 | `var(--c)` = 资源主色 | 与资源 pill 图标同色 |
| 发光 | `box-shadow: 0 0 4px var(--c)` | 微弱光晕 |
| 初始透明度 | 0 | 从不可见开始 |
| 峰值透明度 | 1（20% 时） | 快速显现 |
| 消散透明度 | 0（100% 时） | 渐隐消失 |
| 移动距离 | 0 → -28px（向上 28px） | 从 pill 中上部向上飘 |
| 缩放 | 0.5 → 1 → 0.8 | 先放大再缩小消散 |
| 生命周期 | 0.8s – 1.2s（随机） | `--duration` 生成时随机分配 |
| 缓动 | `var(--ease-out)` | — |
| animation-fill-mode | `forwards` | 结束后保持终态（opacity: 0） |

> **落地注记**：现行 keyframes 无 80% 中间帧（早期设计稿含 80% opacity 0.6 帧，未落地不回改）；粒子 span 直挂 `.res-pill`（`top: 50%; right: 4px`），无专用容器元素（早期设计稿的 `.r-particles` 容器未落地不回改）。

### 3.3 粒子颜色映射

| 资源 | --c 值 | 实际色值 |
|---|---|---|
| energy | `--color-core` 同色系 | #00E5FF |
| crystal | `--color-quantum` 同色系 | #2EE6A0 |
| alloy | `--color-amber` 同色系 | #FFB627 |
| data | `--color-plasma` 同色系 | #A78BFA |
| dark | 灰蓝（暗物质专属色） | #94A3B8 |

> 颜色取自 `stores/resources.ts` 的 `RES_META[].color`（硬编码色值，与 Token 同色系），经 TopBar `resourceList` 以 `--c` 注入。

### 3.4 生成策略（以代码为准）

#### 数量控制

| 参数 | 值 | 说明 |
|---|---|---|
| 每资源最大并发粒子 | 3 | 同时最多 3 个粒子在动画中 |
| 生成间隔 | 400ms | 每 0.4s 生成 1 个粒子 |
| 全局最大粒子数 | 15 | 5 资源 × 3 = 15，硬上限 |
| rate = 0 时 | 不生成 | 无产出无粒子 |
| rate < 0 时 | 不生成 | 负产出不显示粒子（已有红色文字警示） |

#### 生成逻辑

```ts
// composables/useResourceParticles.ts（实现口径）
const GLOBAL_MAX = 15
const PER_RESOURCE_MAX = 3
const SPAWN_INTERVAL = 400  // ms
const DURATION_MIN = 800
const DURATION_MAX = 1200

function spawn() {
  if (document.hidden) return
  const positiveIds = getPositiveRateResources()   // 仅 rate > 0 的资源
  if (positiveIds.length === 0) return
  if (particles.value.length >= GLOBAL_MAX) return

  // 每次随机选一个正产出资源（非逐资源遍历）
  const resId = positiveIds[Math.floor(Math.random() * positiveIds.length)]

  // 单资源上限
  const count = particles.value.filter((p) => p.resourceId === resId).length
  if (count >= PER_RESOURCE_MAX) return

  const id = nextId++
  const duration = DURATION_MIN + Math.random() * (DURATION_MAX - DURATION_MIN)
  particles.value.push({ id, resourceId: resId, duration })

  // 动画结束后移除（与 --duration 同步）
  const timer = setTimeout(() => { /* 按 id 移除 */ }, duration)
}

// start()：prefers-reduced-motion 时不启动；setInterval 400ms
// stop()/visibilitychange：页面不可见停止生成
```

#### 性能优化措施

| 措施 | 说明 |
|---|---|
| CSS 动画而非 JS 动画 | 粒子使用 `@keyframes` + CSS animation，浏览器自动 GPU 合成 |
| 仅 transform + opacity | 不触发 layout/paint |
| setInterval 400ms | 低频生成，不每帧操作 DOM |
| 最大 15 粒子 | 硬上限，5 资源 × 3 |
| visibilitychange 暂停 | 切 tab 时清空粒子，不积压 |
| setTimeout 自动清理 | 每个粒子动画结束后自动从数组移除，定时器卸载时统一清理 + disposed 守卫 |

### 3.5 TopBar 集成方案（以代码为准）

#### DOM 结构

```vue
<!-- TopBar.vue 模板：粒子 span 直挂 res-pill，无容器元素 -->
<li
  v-for="r in resourceList"
  :key="r.id"
  class="res-pill"
  :class="{ flash: r.flash }"
  :style="{ '--c': r.color }"
>
  <svg class="r-icon" style="width: var(--icon-sm); height: var(--icon-sm)" aria-hidden="true">
    <use :href="'#' + r.icon" />
  </svg>
  <span class="r-amount font-mono">{{ r.amount }}</span>
  <span class="r-rate font-mono" :style="{ color: r.color }">{{ r.rate }}</span>
  <!-- 粒子：直挂 pill，绝对定位 top:50% right:4px -->
  <span
    v-for="p in particles.filter(p => p.resourceId === r.id)"
    :key="p.id"
    class="res-particle"
    :style="{ '--c': r.color, '--duration': p.duration + 'ms' }"
  ></span>
</li>
```

> `.res-pill` 需 `position: relative`（现有样式已满足）；`.res-strip` 的 `overflow-x: auto` 不裁切向上飘出的粒子（`overflow-y` 默认 visible）。

### 3.6 粒子动画与资源高亮的关系

| 特性 | 资源变化高亮（§1.6 resFlash） | 资源产出粒子（本章） |
|---|---|---|
| 触发条件 | 资源数值变化（fmt 后字符串不同） | rate > 0（持续产出） |
| 视觉表现 | 数值文字 0.3s 变绿 + 发光 | 向上飘移的光点粒子 |
| 持续时间 | 0.3s 一次性 | 持续生成，rate > 0 期间不断 |
| 语义 | 「数值跳变了」 | 「资源在持续增长」 |

> 两者互补：flash 让玩家感知到数值跳变，粒子让玩家感知到资源在持续流动。

### 3.7 降级方案

#### `prefers-reduced-motion` 降级

```css
@media (prefers-reduced-motion: reduce) {
  .res-particle {
    display: none;
  }
}
```

| 降级项 | 原效果 | 降级后 |
|---|---|---|
| 粒子动画 | particleRise 0.8-1.2s | display: none，无粒子 |

此外生成逻辑在 JS 侧同步降级：`useResourceParticles` 初始化读一次 `matchMedia('(prefers-reduced-motion: reduce)')`，偏好 reduce 时 `start()` 直接不启动；并监听运行时切换（v0.78），从 reduce 切回 normal 时自动恢复生成。

#### 低性能设备降级（建议）

```ts
// 低性能检测（建议阈值）
const isLowPerf = navigator.hardwareConcurrency <= 4

// 降级策略
const PARTICLE_INTERVAL = isLowPerf ? 800 : 400  // 间隔翻倍
const MAX_PARTICLES_PER_RES = isLowPerf ? 1 : 3  // 数量减至 1
```

| 设备等级 | 生成间隔 | 每资源最大粒子 | 全局上限 |
|---|---|---|---|
| 标准 | 400ms | 3 | 15 |
| 低性能 | 800ms | 1 | 5 |

#### 标签页不可见降级（已落地）

`visibilitychange` 时 `document.hidden` 为真即停止生成并清空粒子，可见后恢复。

## 四、氛围循环动画

氛围层循环动画统一登记：均为 `infinite` 循环、纯装饰性质（`aria-hidden` / 不携带信息）、`prefers-reduced-motion` 下降级为静态（全局规则强制 0.01ms，见第六章）。

### 4.1 核心脉动 corePulse

Hero 区核心的呼吸光晕：外圈渗透光晕（`.core-visual::after`）与核心光球（`.core-glow`）同步脉动；App 加载屏的加载核心复用同一 keyframes（2s 周期，更快的加载呼吸感）；桌面侧栏折叠按钮图标（SideNav）亦引用 3s 周期。

```css
@keyframes corePulse {
  0%, 100% {
    transform: scale(1);
    box-shadow:
      0 0 40px rgba(0, 229, 255, 0.4),
      inset 0 0 20px rgba(255, 255, 255, 0.2);
  }
  50% {
    transform: scale(1.08);
    box-shadow:
      0 0 60px rgba(0, 229, 255, 0.6),
      inset 0 0 30px rgba(255, 255, 255, 0.3);
  }
}
```

| 使用点 | 周期 | 位置 |
|---|---|---|
| Hero 核心渗透光晕 + 光球 | 3s ease-in-out infinite | HeroCore.vue |
| App 加载屏加载核心 | 2s ease-in-out infinite | App.vue |
| 侧栏折叠按钮图标 | 3s ease-in-out infinite | SideNav.vue |

### 4.2 核心环旋转 spinRing

Hero 区三层信息环（r1 探索 / r2 科技 / r3 能量）按游戏状态变速旋转，映射规则与相位定义见《氛围视觉规范》P2-3 §2.3，本册仅登记动画参数：

| 环 | 基础周期 | progress 相位 | active 相位 | 方向 |
|---|---|---|---|---|
| r1（探索，量子绿） | 20s | 16s | 12s | 正向 |
| r2（科技，等离子紫） | 15s | 12s | 8s | 反向（reverse） |
| r3（能量，琥珀） | 10s | 8s | 6s | 正向 |

| 参数 | 值 | 说明 |
|---|---|---|
| 缓动 | linear | 连续线性旋转 |
| 相位过渡 | opacity/border-color 0.4s `var(--ease-out)` 平滑过渡 | `animation-duration` 直接切换，旋转连续无跳变 |

### 4.3 光柱呼吸 flowPulse

Hero 底部动线光柱的呼吸动画。落地实现为 `.hero-flow` 独立 div（120×60px 横向椭圆光晕，`blur(4px)` 向下渐隐），非早期设计稿的 `.hero::after` 2px 竖直细线（落地差异见《氛围视觉规范》P2-9 §4.3 注记）。

```css

    opacity: 0.3;
  }
  50% {
    opacity: 0.6;

.hero-flow {

```

| 参数 | 值 | 说明 |
|---|---|---|
| 时长 | 2.5s | 与 corePulse 3s 不同周期（早期设计稿写 3s 同步，落地后各自独立，不回改） |
| 缓动 | ease-in-out | 平滑呼吸 |

### 4.4 星点闪烁 twinkle

## 六、`prefers-reduced-motion` 降级策略

### 6.1 全局规则（唯一出处）

`src/styles/base.css`：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important; /* v0.96：infinite 动画限单次，防 0.01ms 周期下相位随机闪烁 */
    transition-duration: 0.01ms !important;
  }
}
```

全局规则把所有动画/过渡压到 0.01ms，等效瞬时切换。各组件的显式降级声明在此基础上保证「降维后的形态正确」（如位移类动画降级为纯 opacity，不残留 transform 位移）。

### 6.2 各组件显式降级

| 组件/场景 | 原效果 | 降级后 |
|---|---|---|
| 卡片 hover/active | 上浮/缩放 + 变色 | 瞬时切换样式，无位移 |
| 按钮 active | scale(0.95) | 瞬时切换样式 |
| `coreClickPulse` | 0.6s 脉动 | 瞬时放大恢复 |
| `flashSuccess`（预留） | 0.4s 闪光 | 瞬时闪烁 |
| `shakeError`（预留） | 0.3s 抖动 | 不抖动，仅边框色提示 |
| 路由跃迁 warp | warpOut 0.2s + warpIn 0.3s + warpFlash 0.35s | 全局规则瞬时切换（v0.96 起删除独立的 fadeIn 降级声明：此前被全局 `!important` 压掉从未生效，统归 0.01ms 单次） |
| 跃迁 overlay | 白光闪过 | 全局规则瞬时闪过一次即隐（overlay 终态 opacity 0，无背景跳变） |
| 核心环 spinRing | 6-20s 旋转 | 动画静止（0.01ms），opacity 保留状态映射 |
| `flowPulse` 光柱 | 2.5s 呼吸 | 静态光柱 |
| `corePulse` 光晕 | 3s 脉动 | 静态光晕 |
| 星点 twinkle | 2.5-4s 闪烁 | 静止星点 |
| `actionPulse` | 2s 呼吸光晕 | 静态光晕（box-shadow 保留 0% 形态） |
| 资源粒子 | particleRise 0.8-1.2s | 不生成（JS 侧 start() 直接返回）+ `.res-particle { display: none }` 双保险 |
| onboarding 气泡 | floatUp 0.3s | fadeIn 0.15s |
| toast 浮层 | 0.25s 过渡 | 瞬时显隐 |
| 成就 toast（AchievementToast） | 0.25s 过渡 + 位移 | 0.15s 纯 opacity 过渡（transform:none 显式降级） |
| `resFlash` | 0.3s 闪绿 | 瞬时变色 |

### 6.3 运行时监听（粒子）

`useResourceParticles` 除初始化读取外，监听 `matchMedia('(prefers-reduced-motion: reduce)')` 的 `change` 事件（v0.78）：玩家中途开启减弱动画时立即停止生成并清空粒子；关闭时自动恢复。其他纯 CSS 动画由媒体查询自动响应，无需 JS 侧处理。

### 6.4 无障碍关联

焦点策略、aria-live、对比度底线等可达性规范见《交互状态规范》P2-7 与后续 a11y 章节；本册仅承担动效降级维度。
