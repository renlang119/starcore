## 一、世界观设定

- **背景**：公元 2387 年，殖民舰抵达仙女座星系的戴森球遗迹
- **核心主题**：「文明与熵的永恒博弈」，玩家经营星核文明，积累能量、对抗熵增，
  通过「奇点重启」（转生）在轮回中走向更高秩序
- **五层宇宙观**：星核层 → 恒星系层 → 星团层 → 星臂层 → 星系层 → 深空层
  （changelog 转述为「五层」但列出六个名称，原件歧义如实保留；
  当前实现已覆盖前三层：星核层（v0.01 起）、恒星系层（v0.59 起）与星团层（v0.71 起），后续层级为预留扩展空间）
- **设计理念**：从即时满足到永恒成长的分层递进：
  前期建筑/科技提供即时反馈，中期探索/战斗/遗物拉开内容面，
  后期转生循环承载长期成长

## 二、产品定位

- **单机优先、多人预留**（V2.0 口径）：当前阶段纯前端、无后端、无联机内容
- **PVE 为主**（V3.0 口径）：战斗内容为据点 PVE；PVP 仅为远期定位，无实现
- **移动端适配**（V3.0 口径）：桌面侧栏 / 移动底栏双导航，四档响应断点
- **离线收益**：效率固定 100%、无自然衰减（V4.0 口径，取消早期衰减设计）；
  实现侧有 24 小时结算上限，离线 ≥5 分钟才弹收益报告

## 三、系统概览（当前实现）

| 系统 | 内容量 | 说明 |
|---|---|---|
| 资源 | 5 种（能量/晶体/合金/数据/暗物质） | decimal.js 大数 |
| 建筑 | 20 种，分属 5 资源扇区 | 成本递增、科技解锁 |
| 科技树 | 47 项，8 大分支 | 能量/晶脉/材料/计算/军事/探索/暗物质/奇点 |
| 兵种 | 4 种（突击/护卫/重装/灵能） | 双三角克制链 |
| 训练 | 并行槽 1→3 | 「集群操练 I/II」科技扩展（v0.48） |
| 探索 | 16 节点（星核层 4：轨道/内层/外层/深空 + 恒星系层 6 + 星团层 6） | 时间锁定，完成发奖 |
| 据点 PVE | 4 类 21 据点（掠夺者/巨兽/遗迹/沉默者） | 胜利可驻扎挂机 |
| 无尽远征 | 深度递增（上限 999），4 模板轮换 | 敌方 ×0.5×1.25^(d-1)，奖励 ×1.35^(d-1)（v0.60） |
| 遗物 | 20 种，稀有度池抽取 + 同稀有度 3 合 1 合成 | 4 槽位，转生树可 +1；4 组套装分两档加成（v0.61） |
| 转生 | 天赋树（14 买断 + 4 无限）+ 负熵货币 | 奇点重启循环；无限节点成本递增、效果叠加，支出端永不枯竭；3 个自动协议节点常开自动化 |
| 成就 | 34 个，9 类里程碑 | 终身计数跨转生保留，解锁给小额永久加成 |
| 每日签到 | 连击 7 天循环 + 每周 3 项周期挑战 | 签到 tick 自动，断签有回归包（v0.62） |

## 四、数值设计意图（有明确出处的关键决策）

| 决策 | 口径 | 出处 |
|---|---|---|
| 转生阈值 | 3e5 总能量（首转 1.5–3h，前期降流失） | changelog-v0.01-v0.50.md v0.31 |
| 首次转生保底 | 首转 +1 负熵（保底 2，避免买不起任何节点） | changelog-v0.01-v0.50.md v0.33 |
| 转生树无限化 | 买断区保留为引导期目标（v0.56 时 11 节点，v0.58 加 3 协议节点后 14）+ 4 无限节点（全产出 +10%/级、攻防 +5%/级、探索 +10%/级、离线 +10%/级）；成本 ceil(基础 × 增长率^等级)（1.5×，离线 1.6×）。负熵收入 sqrt 压缩增长 vs 成本指数增长 → 等级对数级放缓自收敛；prestige_mult/relic_slot/starting_energy 故意不无限化（正反馈失控/失衡） | v0.56 确定 |
| 自动化 QoL | 转生树 3 买断协议节点（建造 10/研究 10/探索 8 负熵），买后常开只在线生效；每 tick 复用原子操作「买得起即买」，每建筑每 tick 至多 1 级；离线资源照常累积回线后自动化花掉 | v0.58 确定 |
| 成就系统 | 34 成就 9 类，终身计数跨转生保留；拿满 ≈ 全产出 +51%/攻防 +46.9%/探索 +46.1%/离线 +46%/负熵 +10%，量级压在无限树单节点几级内（顺路的糖，非第二权力轴）；prestige_mult 仅集齐遗物 1 个成就给 +10%；老玩家历史产量不追溯（终身计数从装档起算） | v0.57 确定 |
| 离线收益 | 100% 效率无衰减；24h 上限 | V4.0 / 实现 |
| 战斗保底伤害 1 + 50 回合上限 | **软墙设计**：战斗为瞬时结算，该组合表示「越级本该败」，防止低攻编队磨死高防据点；战报有超时撤退文案覆盖 | v0.52 确定 |
| 战斗种子化 | 编队哈希 + 据点 + 分钟级时间派生种子，结果可复现、防 SL 刷随机 | 实现 |
| 训练并行槽 | 基础 1 槽、科技扩展至 3；已在队列任务不受限 | v0.48 确定 |

## 五、技术架构

**技术栈**：Vue 3 + TypeScript + Pinia + Vue Router + Vite +
decimal.js + localforage；纯前端静态站，无后端。

**分层**：

- `src/data/` — 纯数据定义（建筑/科技/兵种/据点/探索/遗物/成就/无尽远征/导航），
  查找走 Map（O(1)）；转生树节点与每日签到模板的数据随 store 定义
  （`src/stores/transcend.ts` / `src/stores/daily.ts`）
- `src/stores/` — 11 个 Pinia store；`src/stores/game.ts` 为中央门面
  （tick 循环、存档、离线收益、转生协调、统一效果系统 EffectSystem）
- `src/views/` — 9 个页面视图；`src/components/` — 布局 + 通用 UI（图标 facade、
  EmptyState、ModalOverlay 等）+ 按视图归位的业务组件（home/、build/ 等）
- `src/lib/` — decimal 封装、格式化、存档（IndexedDB 主存 + localStorage 备份 +
  FNV-1a 校验和 + 全字段白名单校验；版本迁移链已于 v0.73 随 save-migrate.ts
  删除，SAVE_VERSION 重置为 1）、离线收益、效果系统、随机源（fnv1a/mulberry32，v0.73 抽取）

**关键工程口径**：

- store 间不直接互引：跨 store 依赖经 provider 注入（`setRelicSlotProvider` /
  `setTrainingSlotProvider` / `setRelicEnhanceSpendProvider`，v0.70 遗物强化支出通道）
- 原子操作：`tryUpgradeBuilding` / `tryResearch` 检查+扣费+执行一体
- 版本号单一来源：`package.json` → `src/version.ts`（?raw 读取）
- 存档安全边界声明：纯前端无法真正防篡改，校验用于防损坏与意外
