## 二、逐区域评估

### 2.1 TopBar（顶部资源栏）

**现状**：sticky 定位，包含品牌名（仅移动端）+ 5 个资源 pill（图标+数值+产出率）+ 版本号。横向可滚动。

| 维度 | 评价 |
|------|------|
| 布局 | ✅ 简洁，资源一目了然 |
| 间距 | ⚠️ pill 之间 gap 8px 偏紧，5 个资源在窄屏上需要横滑 |
| 字号 | ⚠️ 数值 12px、产出率 10px — 产出率过小，难以快速识别 |
| 冗余 | ❌ **HomeView 的 hero 区域也展示了 4 个环绕资源 + 能量中心，与 TopBar 高度重复** |

**关键问题**：TopBar 资源条在 HomeView 上与 hero 核心视觉信息重复。用户进入主界面后，同一屏内看到两遍晶体/合金/数据流/暗物质量。

### 2.2 SideNav（桌面侧边导航）

**现状**：固定 200px 宽度，包含品牌标识 + 7 个导航项 + 底部统计（转生次数 + 负熵）。sticky 定位，高度 100vh。

| 维度 | 评价 |
|------|------|
| 布局 | ✅ 导航项清晰，图标+文字配合良好 |
| 宽度 | ⚠️ 200px 固定不可折叠，在 768~1024px 的平板/小笔记本上占比偏大 |
| 底部统计 | ⚠️ 转生/负熵放在侧边栏底部，HomeView 的文明概况中也有转生次数 — 信息重复 |
| 品牌区 | ✅ brand-mark 动画效果不错 |

### 2.3 BottomNav（移动端底部导航）

**现状**：fixed 底部，5 个主导航 + "更多"按钮。更多面板向上弹出，右对齐。

| 维度 | 评价 |
|------|------|
| 布局 | ✅ 5+1 的 tab 布局符合移动端惯例 |
| 标签字号 | ⚠️ 10px 偏小，但受限于 6 tab 布局，尚可接受 |
| 更多面板 | ⚠️ right: 4px 右对齐弹出，面板 min-width 120px，小屏下可能溢出左边 |
| 安全区 | ✅ padding-bottom 使用 env(safe-area-inset-bottom)，适配刘海屏 |
| 交互 | ✅ 点击外部自动关闭，路由变化自动收起 |

### 2.4 HomeView — Hero（核心视觉区）

**现状**：160px（移动）/ 180px（桌面）的圆形核心视觉，3 个旋转环 + 光晕 + 中心能量值 + 4 个环绕资源节点。下方显示能量产出率。

| 维度 | 评价 |
|------|------|
| 视觉 | ✅ 科幻氛围感强，环+光晕+脉冲动画效果好 |
| 尺寸 | ⚠️ 160/180px 偏小，作为主界面第一视觉焦点存在感不足 |
| 信息密度 | ⚠️ 环绕节点 11px 字体 + 12px 图标，过小不好辨认 |
| 冗余 | ❌ 4 个环绕资源与 TopBar 完全重复 |
| 交互 | ❌ 核心视觉无交互 — 点击无反应，纯装饰 |
| 产出率 | ⚠️ 12px 显示在下方，不够醒目 |

### 2.5 HomeView — 活跃事件条

**现状**：列出进行中的探索/训练和可升级的建筑/科技，最多 4 条。每条带图标、标签、详情、进度条、箭头。

| 维度 | 评价 |
|------|------|
| 布局 | ✅ 左侧色条 + 图标 + 信息 + 进度，信息层级清晰 |
| 冗余 | ❌ **与下方"推荐行动"高度重叠** — 都会显示"建筑可升级""科技可研究"等 |
| 优先级逻辑 | ⚠️ 进行中(进度<1)优先取 3 条，就绪的取剩余位置。但当同时有 3+ 个进行中和 4+ 个就绪时，部分就绪项被截断 |
| 字号 | ⚠️ 标签 13px、详情 11px — 详情偏小 |

### 2.6 HomeView — 文明概况

**现状**：2 列（移动）/ 3 列（桌面）网格，展示已解锁建筑、已完成科技、部队总数、已装备遗物、游戏时长、转生次数。

| 维度 | 评价 |
|------|------|
| 布局 | ✅ 紧凑的 label-value 卡片，信息密度适中 |
| 冗余 | ⚠️ 转生次数在 SideNav 底部也有显示 |
| 样式 | ⚠️ 每个卡片都是相同的 surface + border，缺乏视觉层次区分 |

### 2.7 HomeView — 推荐行动

**现状**：动态生成情境推荐，每个卡片带彩色图标背景 + 标签 + 描述 + 箭头。

| 维度 | 评价 |
|------|------|
| 布局 | ✅ 大图标 + 文字，可点击区域充足 |
| 冗余 | ❌ **与活跃事件条信息高度重叠** — "X 个建筑可升级"同时出现在两处 |
| 动态性 | ✅ 根据游戏状态智能推荐，设计思路好 |
| 视觉 | ✅ 彩色图标背景 (color-mix 15%) 效果不错 |

### 2.8 全局样式（style.css）

| 维度 | 评价 |
|------|------|
| Design Token | ✅ 完善的 CSS 变量体系，颜色/字体/圆角/动效均有定义 |
| 字体 | ✅ Orbitron(display) + JetBrains Mono(mono) + 系统字体(body)，自托管无 CDN 依赖 |
| 背景 | ✅ 深空星点伪元素，氛围感好 |
| 可访问性 | ✅ prefers-reduced-motion 支持、focus-visible 样式 |
| 对比度 | ✅ 文本颜色层级对比度均达标（t-tertiary #6B7589 on #05070D ≈ 5.3:1） |
| Content max-width | ⚠️ 720px 固定 — 桌面端 SideNav 200px + Content 720px = 920px，在 1200px+ 屏幕上大量留白 |

## 三、优化点清单

### 🔴 建议立即优化（影响用户体验较大）

#### 优化点 1：消除 TopBar 与 HomeView Hero 的资源信息冗余

| 项目 | 内容 |
|------|------|
| **现状** | TopBar 展示 5 种资源（图标+数值+产出率），HomeView Hero 也展示能量中心 + 4 个环绕资源节点。同一屏内资源信息出现两次。 |
| **问题** | 信息冗余，视觉焦点分散。用户在 HomeView 上无法判断该关注哪个资源展示。 |
| **优化建议** | 方案 A（推荐）：HomeView Hero 区域改为**纯视觉/氛围**展示，移除环绕资源数值，只保留能量中心值和产出率。资源详情交给 TopBar。方案 B：TopBar 在 HomeView 路由下隐藏资源条，只在 Hero 展示 — 但这会让其他页面失去全局资源可见性，不推荐。 |
| **预期效果** | 消除冗余，Hero 聚焦"核心能量"单一焦点，TopBar 统一承担资源展示职责。 |
| **优先级** | 高 |
| **改动量** | 轻 |

#### 优化点 2：合并"活跃事件"与"推荐行动"

| 项目 | 内容 |
|------|------|
| **现状** | 活跃事件条显示进行中的探索/训练 + 可升级的建筑/科技。推荐行动也显示可升级建筑数、可研究科技数、可探索节点数、训练中部队数。两者信息重叠严重。 |
| **问题** | 用户看到"建筑可升级"出现在事件条，又看到"1 个建筑可升级"出现在推荐行动，困惑该点哪个。功能完全一致的入口被重复展示。 |
| **优化建议** | 合并为单一"行动队列"模块，分两类展示：① **进行中**（带进度条）：探索、训练；② **可执行**（带箭头）：可升级建筑、可研究科技、可探索节点。每条只出现一次，点击跳转对应页面。 |
| **预期效果** | 消除信息冗余，减少用户决策负担，缩短页面长度。 |
| **优先级** | 高 |
| **改动量** | 中 |

#### 优化点 3：增大 Hero 核心视觉尺寸与交互性

| 项目 | 内容 |
|------|------|
| **现状** | 核心视觉 160px（移动）/ 180px（桌面），纯装饰不可交互，中心数值 20px/22px。 |
| **问题** | 作为主界面的第一视觉焦点，尺寸过小、存在感不足。无交互意味着这块区域"浪费"了。 |
| **优化建议** | ① 尺寸增至 200px（移动）/ 240px（桌面）；② 中心能量值字号增至 24px/28px；③ 点击核心可跳转至建造页或展示详细资源面板；④ 产出率显示更醒目（14px，带 "/s" 单位强调）。 |
| **预期效果** | 强化主界面视觉冲击力，增加可交互面积，让核心视觉"活起来"。 |
| **优先级** | 高 |
| **改动量** | 中 |

#### 优化点 4：小字号文本提升可读性

| 项目 | 内容 |
|------|------|
| **现状** | 多处使用 10px（版本号、底部导航标签、core-label）、11px（环绕资源数值、事件详情、推荐描述）。 |
| **问题** | 10-11px 在高 DPI 移动端尚可，但在桌面端常规 DPI 下偏小，影响快速阅读。 |
| **优化建议** | ① 底部导航标签 10px → 11px；② 环绕资源数值（若保留）11px → 12px；③ 事件详情 11px → 12px；④ 推荐描述 11px → 12px；⑤ 版本号保持 10px（次要信息）。 |
| **预期效果** | 提升全局可读性，减少用户眯眼/放大操作。 |
| **优先级** | 高 |
| **改动量** | 轻 |

### 🟡 可选优化（锦上添花）

#### 优化点 5：桌面端内容区域宽度自适应

| 项目 | 内容 |
|------|------|
| **现状** | Content 区域 max-width: 720px 居中。SideNav 200px + Content 720px = 920px 最小需求。在 1200px+ 屏幕上，内容区两侧大量留白。 |
| **问题** | 大屏桌面空间利用率低。HomeView 的卡片网格只有 3 列，大屏下卡片过宽。 |
| **优化建议** | ① 桌面端 Content max-width 提升至 960px 或 1080px；② 或改为 `max-width: calc(100vw - 200px - 48px)` 自适应；③ 配合调整 overview-grid 在大屏下为 4 列。 |
| **预期效果** | 充分利用桌面屏幕空间，信息密度更合理。 |
| **优先级** | 中 |
| **改动量** | 轻 |

#### 优化点 6：SideNav 可折叠

| 项目 | 内容 |
|------|------|
| **现状** | 固定 200px 宽度，不可折叠。 |
| **问题** | 在 768~1024px 的平板/小笔记本上，200px 占比 20%~26%，压缩了内容区。 |
| **优化建议** | 增加折叠功能：折叠后仅显示图标（48px 宽），展开恢复 200px。折叠状态记忆到 localStorage。 |
| **预期效果** | 提升中小屏桌面端的灵活性。 |
| **优先级** | 中 |
| **改动量** | 中 |

#### 优化点 7：SideNav 底部统计去重

| 项目 | 内容 |
|------|------|
| **现状** | SideNav 底部显示转生次数 + 负熵。HomeView 文明概况也显示转生次数。 |
| **问题** | 转生次数信息重复。 |
| **优化建议** | SideNav 底部只保留负熵（转生系统独有指标），转生次数统一由 HomeView 文明概况展示。或反过来，HomeView 去掉转生次数，统一在 SideNav。 |
| **预期效果** | 消除信息冗余，各区域职责明确。 |
| **优先级** | 中 |
| **改动量** | 轻 |

#### 优化点 8：文明概况增加视觉层次

| 项目 | 内容 |
|------|------|
| **现状** | 6 个 ov-item 样式完全一致（surface + border-line），无视觉差异。 |
| **问题** | 所有指标看起来同等重要，缺乏层次感。实际上"已完成科技"和"游戏时长"的重要性不同。 |
| **优化建议** | ① 关键指标（如已解锁建筑、已完成科技）用左侧色条或微妙的背景渐变强调；② 或对数值使用不同颜色（如科技用 plasma 紫、部队用 alert 红）；③ 适当增加图标。 |
| **预期效果** | 概览区视觉层次更分明，用户快速定位关键信息。 |
| **优先级** | 中 |
| **改动量** | 轻 |

#### 优化点 9：TopBar 资源 pill 优化

| 项目 | 内容 |
|------|------|
| **现状** | 5 个资源 pill 横向排列，gap 8px，窄屏需横滑。产出率 10px 显示在数值旁。 |
| **问题** | 横滑隐藏了部分资源，用户可能不知道还有资源被遮挡。产出率过小。 |
| **优化建议** | ① 产出率提至 11px，加轻微背景色区分；② 考虑在资源 pill 右侧加渐变遮罩提示可滑动；③ 或在移动端将能量单独突出（主资源），其余 4 个缩小展示。 |
| **预期效果** | 提升资源可见性，减少横向滑动带来的信息遗漏。 |
| **优先级** | 中 |
| **改动量** | 轻 |

#### 优化点 10：BottomNav "更多"面板位置优化

| 项目 | 内容 |
|------|------|
| **现状** | 更多面板 right: 4px 右对齐弹出，min-width 120px。 |
| **问题** | 在极窄屏幕（<360px）上面板可能溢出左侧边缘。 |
| **优化建议** | 改为 right: 0，面板宽度改为 `min(160px, calc(100vw - 16px))`，确保不溢出。同时增加左侧渐变阴影提示弹出方向。 |
| **预期效果** | 增强小屏兼容性。 |
| **优先级** | 低 |
| **改动量** | 轻 |

#### 优化点 11：HomeView 增加快速操作入口

| 项目 | 内容 |
|------|------|
| **现状** | Hero 区域纯装饰，用户需要滚动到下方才能找到操作入口。 |
| **问题** | 首屏交互面积少，主要被装饰性元素占据。 |
| **优化建议** | 在 Hero 下方（或浮于 Hero 右侧）增加一行紧凑的快速操作按钮（如"一键升级"或"收集"），让首屏即有可操作内容。需结合游戏机制设计。 |
| **预期效果** | 提升首屏交互密度，减少滚动操作。 |
| **优先级** | 低 |
| **改动量** | 中 |

#### 优化点 12：加载状态与空状态优化

| 项目 | 内容 |
|------|------|
| **现状** | App.vue 有 loading-screen 初始化动画。HomeView 的活跃事件条和推荐行动在无内容时有默认兜底，但视觉上缺乏引导。 |
| **问题** | 新玩家首次进入时，活跃事件为空、推荐行动只有默认 2 条，页面显得"空旷"。 |
| **优化建议** | ① 活跃事件为空时，显示一段引导文案（如"暂无进行中的任务，去建造或探索吧"）；② 新玩家首屏增加 onboarding 提示气泡。 |
| **预期效果** | 改善新玩家首次体验。 |
| **优先级** | 低 |
| **改动量** | 中 |
