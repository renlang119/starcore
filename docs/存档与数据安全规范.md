## 一、存储架构

双通道存储，互为备份：

| 通道 | 载体 | 键 | 用途 |
|---|---|---|---|
| 主存 | IndexedDB（localforage 实例 `starcore/save`） | `starcore_save_v1` | 常规读写 |
| 备份 | localStorage | `starcore_save_v1_backup` | 主存不可用时的恢复源 + beforeunload 同步落盘 |

- 两通道均写入 `{ d: JSON字符串, c: 校验和 }` 载荷，校验和用 FNV-1a 哈希（`lib/random.ts`）
- 写入顺序：先 IndexedDB 后主备 localStorage，任一失败静默回退，不中断游戏
- 同步写入 `writeSaveSync` 只落 localStorage 备份通道（beforeunload 场景等不及 IndexedDB）

## 二、存档版本机制

- 现行 `SAVE_VERSION = 1`（测试阶段重新起算；旧版本迁移链已随 v0.73 精简移除）
- **版本过新拒绝**：存档 version 高于当前版本时拒绝读取/导入（不静默 hydrate 未知结构），走「版本过新」错误屏
- 版本低于当前版本：现行无迁移链，遇到 version < 1 按损坏处理（清档重开）
- 新增需改存档结构的玩法时：双格式校验器必须同时接受新旧格式（校验跑在迁移之前），随后 hydrate 内迁移，SAVE_VERSION 递增

## 三、读取链路

`readSave()` 双通道都尝试，取 `savedAt` 更新的一档：

| 结果态 | 判定 | 后续 |
|---|---|---|
| ok | 任一通道路径解析 + 校验通过 | 正常 hydrate 启动 |
| too_new | version 高于 SAVE_VERSION | 错误屏，提示版本过新 |
| corrupt | 双通道有存储值但都不可用 | 错误屏，可导出原始存档后清档 |
| none | 双通道都无值 | 新档启动 |

定标细节：

- 双档比较取 `savedAt` 新者；同值（含双损坏的 -1 垫底）时 **IndexedDB 主档优先**（`>=` 保序先到者）
- corrupt 与 none 严格区分：有存储值即不可静默清档、不可用空状态覆盖（v0.75 缺陷教训）
- corrupt 态附带 localStorage 备份通道的原始载荷（`raw`），供错误屏导出

## 四、校验与自愈

校验器 `_validateAndRepair` 跑在迁移之前，必须接受新旧双格式。两层防线：

### 结构校验（拒绝项，任一不过整档判废）

- 数值串白名单正则（拒绝空串/负数/非数值串/超指数位）
- 存档 id 白名单（建筑/科技/兵种/探索节点/据点/遗物池）
- 负熵非有限值钳 0；无限节点等级 ≤ 1e6；训练 count 整数
- 玩家名字段类型与长度（字符串、上限 24 字符）
- version 上限（过新拒绝，见 §二）

### 自愈项（不改语义，可推导的缺失补齐）

| 自愈项 | 来源 | 行为 |
|---|---|---|
| 通关集混入 `endless` | v0.60 远征胜利登记缺陷 | 剥离该条目继续，不整档拒绝 |
| 编队空数组 | v0.81 发现 | 补默认三支编队（hydrate 后直接读编队会崩） |

## 五、写入守卫

| 守卫 | 实现 |
|---|---|
| 错误态拒绝一切写入 | `game.initError` 置位时 save/saveSync/doImport 直接返回（防空状态覆盖原始存档） |
| 卸载兜底 | beforeunload 同步写 localStorage 备份；错误态不挂该钩子 |
| 转生 totals 语义 | totals 只累计生产/gain（setAmount 属注入语义不入 totals）；转生清零是设计意图，成就侧终身计数先采集 |
| 转生保留清单 | 跨转生保留：遗物、负熵与天赋树、转生次数、成就、暗物质、无尽远征最深层；其余全清 |

## 六、导入流程

导入是**破坏性全量替换**：`doImport` 先全量 reset（含 totalTranscends 可清零），再 hydrate 导入档，成功后刷新页面。

### 三段拒绝（`importSave`）

| 拒绝原因 | 判定 | 提示口径 |
|---|---|---|
| invalid | 空串 / 非 Base64 / 伪 JSON / 无 SCB- 前缀 | 导入失败：存档无效 |
| corrupted | Base64 可解但校验不过 | 导入失败：存档无效（同口径） |
| too_new | version 高于当前 | 导入失败：存档来自更新版本 |

### 确认流（破坏性操作二次确认）

导入按钮点击后先弹确认框，文案定标：「导入将**完全替换**当前存档，
当前进度不可恢复。确认导入？」确认后才执行解析与替换（实现见
《弹窗与确认流规范》§三）。

### 已知限制

- 含 `__proto__` 等未知键的档在结构白名单处整档拒绝：代码无专门键名黑名单，实防线为 `_isObject` 结构白名单逐键校验，未知键所在子对象的白名单不含该键即判 corrupted 整档拒收，效果等同键名拦截（Object.prototype 未被污染，v0.87 安全矩阵实测）
- 解析失败不触碰现有存档（先解析校验，全过后才 reset）

## 七、导出

| 项 | 定标 |
|---|---|
| 编码 | Base64(JSON)，前缀 `SCB-`（旧 `SCE-` 前缀兼容可读） |
| 剪贴板 | 优先 `navigator.clipboard`，失败静默（http 非安全上下文可能不可用） |
| 常显 | 导出后存档码**常显**在只读文本域（不再仅失败时回退），focus 自动全选 |
| 时长提示 | 导出成功提示 5s（「已导出并复制到剪贴板，存档码同时显示在下方」） |
| 原始档导出 | 仅 corrupt 错误屏提供：损坏载荷下载为 `.json`（`starcore-corrupt-save-时间戳.json`），交玩家自行留存 |

## 八、错误屏与运行期兜底

启动读取失败或运行期未捕获异常时的全屏兜底屏（App.vue）：

| 态 | 标题 | 提示文案 | 出口 |
|---|---|---|---|
| too_new | 星核读取失败 | 存档来自更新版本的游戏，当前版本无法读取。 | 仅清除存档重开 |
| corrupt | 星核读取失败 | 存档数据已损坏，无法读取。可先导出原始存档，再清除重开。 | 导出原始存档 + 清除存档重开 |
| failed | 星核读取失败 | 存档数据异常，读取失败。 | 仅清除存档重开 |
| runtime | 星核运行异常 | 游戏运行遇到异常。建议先刷新页面重试；若问题反复出现，可清除存档重开。 | 刷新页面 + 导出存档 + 清除存档重开 |

- runtime 态由 `main.ts` 注册的全局错误处理器置位（渲染、生命周期与
  事件处理中的未捕获异常）；运行期兜底不阻断自动存档与卸载兜底，
  刷新即恢复
- runtime 态的「导出存档」= 当前存档码下载为 .txt 文本文件，可经
  导入入口恢复
- 「清除存档重开」= `hardReset()` 全清后新档启动，手动点击执行，不自动清档
- 启动错误三态期间不挂 beforeunload、不写存档（守卫见 §五）

## 十、安全边界声明

存档安全的目标是**防意外不防恶意**：

- Base64 + 校验和可过滤肉眼可读、无意识复制粘贴、偶发损坏
- 不能防御有目的的查看/篡改（atob 即可解码）；若需更高安全性须引入服务端签名，本项目为纯前端无后端，明确不做
- 玩家本机即信任边界：所有校验服务于「坏档不炸游戏、不误覆盖好档」
