## P3-2 HomeView 快速操作入口

### 2.1 设计目标

在 Hero 核心区下方增加一行紧凑的快速操作按钮，让玩家首屏即可一键跳转到核心功能页（建造/科技/探索/部队），无需依赖底部导航或侧边导航。

**设计原则**：
- 视觉重量低于 Hero 核心和行动队列，作为"辅助快捷通道"存在
- 按钮样式沿用 P1-5 按钮系统，不新增按钮类型
- 4 个按钮等宽排列，图标 + 文字组合，色彩与各系统主色对应

### 2.2 布局位置

```
┌─────────────────────────────────────────┐
│              Hero 核心区                 │
│           (能量值 + 产出率)              │
├─────────────────────────────────────────┤
│  [⚡建造]  [🔬科技]  [🧭探索]  [⚔️部队]  │  ← 快速操作入口（新增）
├─────────────────────────────────────────┤
│            行动队列模块                  │
│         (进行中 / 可执行)                │
├─────────────────────────────────────────┤
│            文明概况                       │
└─────────────────────────────────────────┘
```

**DOM 位置**：`.home-top-row` 的后续兄弟节点（桌面在 Hero+队列整行之下，移动在队列之后），不在 home-top-row 内部。

> **实现注记（v0.86）**：原设计将快速操作入口放在 `.home-top-row` 内部（Hero 之后、行动队列之前）；实际实现（QuickActions.vue 在 HomeView 模板中位于 `.home-top-row` 之后、DailyCard 之前）为其后续兄弟节点，以代码为准。

### 2.3 按钮定义

| 序号 | 标签 | 图标 | 跳转路径 | 主色 | 图标 ID |
|------|------|------|---------|------|---------|
| 1 | 建造 | 🔨 | `/build` | `--color-core` (#00E5FF) | `i-nav-build` |

### 2.4 按钮样式规范

> **落地差异（v0.83 回写）**：`.quick-actions` 实现为 `display: grid;
> grid-template-columns: repeat(4, 1fr)`（等宽四列，QuickActions.vue），
> 非本节原稿的 `display: flex`；按钮布局为纵向图标+文字堆叠
> （flex-direction: column），非原稿的横向 inline-flex 图标行；
> 图标尺寸统一 `var(--icon-md)`（原稿独立 `.qa-icon` 包装类已不存）；
> 无障碍以 section `aria-label="快速操作"` + 图标 `aria-hidden` 实现
> （原稿无 role 口径）。以下原稿保留为历史设计。

## P3-3 加载与空状态优化

### 3.1 设计目标

为各页面的空状态（无数据/无内容）提供引导文案，并为新玩家首次进入各页面时提供 onboarding 气泡提示，降低理解门槛。

**两部分**：
1. **空状态文案规范**：各页面在无数据时显示的引导文案
2. **新手 onboarding 气泡**：首次进入页面时的功能引导气泡

### 3.2 空状态文案规范

#### 3.2.1 统一视觉样式

空状态封装为通用组件 `src/components/ui/EmptyState.vue`，样式复用全局
`.empty-state` 体系（`src/styles/utilities.css`，早期写 `style.css`）：

```css
.empty-state {
  display: flex;
  flex-direction: column;
  align-items: center;
  gap: var(--space-2);
  padding: var(--space-6) var(--space-4);
  text-align: center;
}

.empty-state .empty-icon {
  color: var(--color-t-tertiary);
  opacity: 0.5;
  /* 图标尺寸 32px（组件内联 width/height） */
}

.empty-state .empty-text {
  font-size: var(--text-sm);
  color: var(--color-t-tertiary);
}

.empty-state .empty-hint {
  font-size: var(--text-xs);
  color: var(--color-t-tertiary);
  opacity: 0.7;
}

.empty-state .es-action {
  margin-top: var(--space-2);
}
```

| 参数 | 值 | 说明 |
|------|------|------|
| 布局 | flex column center | 居中堆叠 |
| padding | `var(--space-6) var(--space-4)` (24/16) | 宽松留白 |
| gap | `var(--space-2)` (8px) | 元素间距 |
| 图标尺寸 | 32px（内联） | 大图标 |
| 图标颜色 | `var(--color-t-tertiary)` opacity 0.5 | 弱化 |
| 主文案 font-size | `var(--text-sm)` (14px) | 标准正文 |
| 主文案颜色 | `var(--color-t-tertiary)` (#7A8699) | 弱化文本 |
| 提示文案 font-size | `var(--text-xs)` (12px) | 小字 |
| 提示文案颜色 | `var(--color-t-tertiary)` + opacity 0.7 | 更弱 |
| 引导按钮 | `.btn-secondary.sm` | P1-5 按钮系统；仅传 `to` 时跳转路由，否则 emit `action` |

#### 3.3.4 触发逻辑

```ts
// composable: useOnboarding.ts
const STORAGE_KEY = 'starcore_onboarding'

// 存储结构：JSON 对象，每个 step 一个 boolean（step id 见 §3.3.3 表）
// 如 { "home-core": true, "build-upgrade": true }

function loadCompleted(): Set<string> {
  try {
    const raw = localStorage.getItem(STORAGE_KEY)
    if (!raw) return new Set()
    const obj = JSON.parse(raw) as Record<string, boolean>
    return new Set(Object.keys(obj).filter((k) => obj[k] === true))
  } catch {
    return new Set()
  }
}

function saveCompleted(set: Set<string>) {
  const obj: Record<string, boolean> = {}
  for (const s of set) obj[s] = true
  localStorage.setItem(STORAGE_KEY, JSON.stringify(obj))
}
```

| 规则 | 说明 |
|------|------|
| 存储方式 | localStorage，key = `starcore_onboarding` |
| 数据结构 | JSON 对象，每个 step 一个 boolean |
| 显示条件 | `state[stepId] !== true`（未 dismiss 过） |
| dismiss 触发 | ① 点击「知道了」按钮 ② 点击「跳过引导」（skipAll 整个流程） ③ 10 秒超时自动关闭（**仅关闭不写入**） |
| 路由切换 | 气泡随组件卸载消失，**不写入** localStorage，下次进入该页会重新显示 |
| dismiss 后 | 永久不再显示该 step（除非清 localStorage） |
| 多气泡顺序 | 同一页面多个气泡按顺序显示（前一个 dismiss 后才显示下一个） |
| 超时 | 10 秒后自动关闭 |
| 转生后 | 不重置 onboarding 状态（已学过不再打扰） |

#### 3.3.5 dismiss 行为详细

```ts
// 气泡显示时（实现：useOnboarding.ts）
function startTimeout() {
  clearTimer()
  // 10s 超时仅关闭，不写入 localStorage
  timer = setTimeout(() => { activeStep.value = null }, TIMEOUT_MS)
}

// dismiss 时（「知道了」按钮）
function dismiss() {
  if (activeStep.value) {
    const completed = loadCompleted()
    completed.add(activeStep.value)
    saveCompleted(completed)   // 写入 localStorage
  }
  clearTimer()
  // 推进到下一个未完成的 step
  const next = steps.find((s) => !loadCompleted().has(s))
  activeStep.value = next ?? null
  if (activeStep.value) startTimeout()
}

// 跳过引导（「跳过引导」按钮）：整个流程全部标记完成
function skipAll() {
  const completed = loadCompleted()
  for (const s of steps) completed.add(s)
  saveCompleted(completed)
  clearTimer()
  activeStep.value = null
}
```

| dismiss 方式 | 立即关闭 | 写入 localStorage | 说明 |
|-------------|:---:|:---:|------|
| 点击「知道了」 | ✅ | ✅ | 主动关闭并推进下一气泡 |
| 点击「跳过引导」 | ✅ | ✅（全部 step） | 跳过当前页整个流程 |
| 10 秒超时 | ✅ | ❌ | 仅关闭，下次进入仍显示 |
| 路由切换 | ✅ | ❌ | 组件卸载即消失，未写入 |
| 页面刷新 | — | ✅（已写入） | 刷新后不再显示 |

## P3-4 四档响应断点

### 4.1 设计目标

将现有单一 768px 断点扩展为四档响应式体系，覆盖移动/平板/桌面/宽屏四类设备，精细化利用不同屏幕空间。

**四档断点**：

| 档位 | 名称 | 宽度范围 | 定位 |
|------|------|---------|------|
| S | Mobile | <768px | 单手操作，竖屏为主 |
| M | Tablet | 768px – 1023px | 横屏平板，小笔记本 |
| L | Desktop | 1024px – 1439px | 标准桌面显示器 |
| XL | Wide | ≥1440px | 大屏/外接显示器 |

> **768px 保持不变**：与现有 `useBreakpoint.ts` 的 `MOBILE_BREAKPOINT = 768` 一致，不影响 SideNav/BottomNav 的切换逻辑。新增 1024/1440 两档仅影响布局参数，不影响导航切换。

### 4.4 useBreakpoint 扩展建议

> **状态（v0.83 注记）**：本节四档 API（`Breakpoint` 类型 / `breakpoint` ref）为
> 设计建议，未落地——v0.78 行为卫生清理已删除无消费方的断点预留实现，
> `useBreakpoint.ts` 现仅导出 `isDesktop`。以下代码保留为历史设计稿，若未来
> 出现真实消费方再按此实现。

现有 `useBreakpoint.ts` 仅返回 `isDesktop`（≥768px）。P3-4 建议扩展为四档，供组件按需使用：

```ts
// useBreakpoint.ts 扩展（不破坏现有 isDesktop）
export type Breakpoint = 'S' | 'M' | 'L' | 'XL'

export function useBreakpoint() {
  const isDesktop = ref(true)
  const breakpoint = ref<Breakpoint>('S')

  function update() {
    const w = window.innerWidth
    isDesktop.value = w >= 768
    if (w < 768) breakpoint.value = 'S'
    else if (w < 1024) breakpoint.value = 'M'
    else if (w < 1440) breakpoint.value = 'L'
    else breakpoint.value = 'XL'
  }

  // ... 其余逻辑不变

  return { isDesktop, breakpoint }
}
```

> **注意**：`isDesktop` 保持不变，SideNav/BottomNav 切换逻辑不受影响。`breakpoint` 为新增返回值，组件可选使用。CSS 媒体查询为主，JS 断点仅为需要 JS 逻辑判断的场景准备（如动态计算列数）。

### 4.5 响应式行为约束

| 约束 | 说明 |
|------|------|
| 无 FOUC | 断点切换不闪烁。CSS 媒体查询即时生效；JS 断点在 setup 阶段初始求值（已有模式） |
| 移动端优先 | 基准样式为 S 档，M/L/XL 逐级覆盖 |
| 导航切换仅在 768px | SideNav/BottomNav 切换不随 1024/1440 变化 |
| 渐进增强 | 从 S→M→L→XL，每档仅调整尺寸/间距/列数，不改变 DOM 结构 |
| 文字不缩放过大 | 最大字号 `--text-display` (39px)，XL 档不再放大字号，仅放大间距和核心视觉 |
